# BountyOS — учебный прототип для Bug Bounty Operations

**Личный экспериментальный проект · Product / Project Management · Python / FastAPI**

## Зачем я это делал

Я хотел на практике познакомиться с тем, как может быть устроен технический продукт для управления процессами Bug Bounty: от списка разрешённых активов до обработки отчётов, проверки повторов и аналитики. Это самостоятельная проба работы с продуктовой идеей и кодом, **не коммерческий продукт и не решение для реальных компаний**.

## Что реализовано

- **BountyScope** — программы и разрешённые активы.
- **ReportFlow** — создание отчётов и управление статусами.
- **DuplicateHunter** — подсказки похожих отчётов на основе текстового сходства (не AI).
- **BountyScore** — базовая оценка приоритета.
- **BountyPulse** — события и простая аналитика.
- **BountyOS Web** — единый локальный браузерный интерфейс.

Пять отдельных API-сервисов используют FastAPI и SQLite; предусмотрены Dockerfile, базовые API-тесты и локальный запуск. Веб-интерфейс построен на HTML/CSS/JavaScript.

## Мой продуктовый подход

В рамках эксперимента я описал пользователей и сценарии, наметил метрики, риски и последовательность развития. В [`PRODUCT_PLAN.md`](PRODUCT_PLAN.md) находятся продуктовая гипотеза, персоны, пример приоритизации RICE и roadmap. Эти оценки **гипотетические**: пользовательских исследований и подтверждённых бизнес-результатов нет.

Главная цель — попробовать связать постановку задачи, проектирование процессов и реализацию простого технического прототипа.

## Как запустить локально (Windows)

Нужен установленный Python и зависимости проекта. В корне папки:

```powershell
python -m pip install -r bountyos-web/requirements.txt
python -m pip install -r bounty-scope/requirements-dev.txt
python start.py
```

Откройте `http://127.0.0.1:8080`. API-документация доступна на портах `8101`–`8105` по пути `/docs`. Также для пяти backend-сервисов предусмотрен `docker compose up --build` (без веб-интерфейса).

Подробнее: [`START_HERE_v04.md`](START_HERE_v04.md) и [`DEMO_SCENARIO.md`](DEMO_SCENARIO.md).

## Ограничения и дальнейшие шаги

Это **локальный учебный прототип**, а не production-ready система. Нет полноценной авторизации и RBAC, транзакционной согласованности между сервисами, надёжного обмена событиями и необходимых защит для публичного развёртывания. Не следует загружать реальные конфиденциальные отчёты или публиковать сервер в интернете.

Потенциальные следующие шаги: контракты событий, интеграционные тесты, авторизация, улучшение интерфейса и измерение качества подсказок по дубликатам.
